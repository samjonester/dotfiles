# Herdr Configuration

Personal [herdr](https://herdr.dev) agent-multiplexer configuration. Everything herdr reads that is _authored_ lives here and is symlinked or registered into `~/.config/herdr` by `personal/install.sh` → `setup_herdr()`. Everything herdr _writes_ (session state, logs, plugin checkouts) stays machine-local and is deliberately not versioned.

## Directory layout

```
personal/herdr/
├── config.toml        → ~/.config/herdr/config.toml    theme, sidebar, keybindings
├── layouts.toml       → ~/.config/herdr/layouts.toml   worktree-layouts templates (optional)
├── plugins.installs   Pinned third-party plugins: owner/repo[/subdir]@<sha>
└── plugins/           Locally-authored plugins, registered with `herdr plugin link`
    └── launcher/      fzf modal over shortcuts, running agents, and files
```

Applied by `setup_herdr()` in `personal/install.sh`. `setup_herdr_pi()` runs separately, after `setup_pi()`, because it writes into `~/.pi/agent/`.

## What is not versioned, and why

| Path                                                           | Why                                                                                            |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `~/.config/herdr/session.json`, `sessions/`, `*.log`, `*.sock` | Live server state                                                                              |
| `~/.config/herdr/plugins/github/`                              | Managed checkouts — reproduced from `plugins.installs`                                         |
| `~/.config/herdr/plugins.json`                                 | Registry herdr rebuilds from install/link                                                      |
| `~/.config/herdr/plugins/config/<id>/`                         | Plugin-owned config dir. Version the file here and symlink it if a plugin needs durable config |
| `~/.pi/agent/extensions/herdr-agent-state.ts`                  | Generated by `herdr integration install pi`                                                    |
| `~/.pi/agent/skills/herdr/SKILL.md`                            | Generated by `herdr --skill` — regenerating keeps it from drifting from the installed binary   |

The binary itself is installed per-OS: `brew install herdr` on macOS, `curl -fsSL https://herdr.dev/install.sh | sh` on linux. `config.toml` sets `update.version_check = false` because `herdr update` is the wrong upgrade path for a brew install.

## Third-party plugins

One `owner/repo[/subdir]@<git-ref>` per line in `plugins.installs`. The ref is required — `herdr plugin install` without `--ref` resolves whatever HEAD happens to be, and the resolved commit is only ever recorded in the unversioned `plugins.json`. An unpinned or empty-ref line is skipped with a warning rather than installed loosely.

Adding one:

```bash
# find the commit you want, then
echo 'owner/repo/subdir@<sha>' >> personal/herdr/plugins.installs
herdr plugin install owner/repo/subdir --ref <sha> --yes
```

Reinstalling replaces the managed checkout, so bumping a pin is just editing the line and re-running. `herdr plugin uninstall <id>` removes both the registration and the checkout.

## Authoring a local plugin

A plugin is a directory holding `herdr-plugin.toml` plus any executable — bash, python, node, a compiled binary. There is no SDK: the whole herdr CLI is the plugin API, reached through `$HERDR_BIN_PATH`.

1. `mkdir personal/herdr/plugins/<name>` and write `herdr-plugin.toml`
2. `herdr plugin link ~/dotfiles/personal/herdr/plugins/<name>`
3. Reload or restart the herdr server to pick up manifest changes

`plugin link` registers the directory **in place** — it does not copy — so the dotfiles checkout stays the live source and edits take effect without reinstalling. `setup_herdr()` links every subdirectory of `plugins/` that contains a manifest, so a new machine picks it up automatically. `herdr plugin unlink <id>` deregisters without touching files. Installing a GitHub plugin over a linked one is refused, so the two paths cannot collide.

Minimal manifest:

```toml
id = "sam.example"
name = "Example"
version = "0.1.0"
min_herdr_version = "0.8.0"
description = "What it does"
platforms = ["macos", "linux"]

[[actions]]
id = "run"
title = "Run example"
contexts = ["workspace"]
command = ["bash", "run.sh"]
```

Manifest sections: `[[build]]` (GitHub installs only — `plugin link` never builds), `[[startup]]` (once per server start, one-shot not a daemon), `[[actions]]`, `[[events]]`, `[[panes]]`, `[[link_handlers]]`.

Event names herdr 0.8.2 emits include `worktree.created`, `worktree.opened`, `worktree.removed`, `workspace.created`, `workspace.closed`, `workspace.renamed`, `tab.created`, `tab.closed`, `tab.renamed`, `pane.created`, `pane.closed`, `pane.exited`, `pane.agent_detected`, `pane.agent_status_changed`, `pane.output_matched`.

Every command runs with the plugin dir as cwd and receives `HERDR_BIN_PATH`, `HERDR_SOCKET_PATH`, `HERDR_ENV=1`, `HERDR_PLUGIN_ID`, `HERDR_PLUGIN_ROOT`, `HERDR_PLUGIN_CONFIG_DIR`, `HERDR_PLUGIN_STATE_DIR`, `HERDR_PLUGIN_CONTEXT_JSON`, plus `HERDR_WORKSPACE_ID` / `HERDR_TAB_ID` / `HERDR_PANE_ID` when available. Call herdr through `$HERDR_BIN_PATH`, not a bare `herdr`. Write user config to `$HERDR_PLUGIN_CONFIG_DIR` and runtime state to `$HERDR_PLUGIN_STATE_DIR` — never to `$HERDR_PLUGIN_ROOT`, which for GitHub installs is a managed checkout.

Bind an action to a key in `config.toml`:

```toml
[[keys.command]]
key = "prefix+e"
type = "plugin_action"
command = "sam.example.run"
```

Debug with `herdr plugin action list`, `herdr plugin action invoke <plugin.id>.<action>`, `herdr plugin log list --plugin <id>`.

### `launcher`

`prefix+space` opens one fzf modal with four tabs, cycled with `tab` / `shift-tab` or by clicking the header strip. `?` shows the key list for whichever tab is current — which also means `?` cannot be typed into the query. The right pane previews whatever row is under the cursor.

| Tab     | Rows                                                                         | Preview                                                     | Enter                                                | Other keys                                                                            |
| ------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Actions | Every effective binding, grouped, with a description — no chords in the list | The chord to press, and which of the three things Enter does | Runs it, jumps to the tab that supersedes it, or hands back its chord | —                                                                                     |
| Agents  | Running agents, searchable by task, workspace, and tab                       | Status, place, cwd, session id, and the live screen         | Focus that pane                                      | `ctrl-y` copy session id                                                              |
| Spaces  | Workspaces, then the tabs of the one you pick                                | The workspace's tabs; then that tab's panes and live screen | Opens the space, then focuses the tab                | `esc` back out, `ctrl-n` new workspace / new tab                                      |
| Files   | `fd` under a root that starts at the focused pane's cwd                      | `bat`                                                       | Open in `$VISUAL` in a pane split off the active one | `ctrl-y` copy path, `ctrl-r` change root, `ctrl-h` include dotfiles and ignored files |

Spaces is two levels deep in one tab. Enter on a workspace swaps the left pane for that workspace's tabs and the preview for the tab detail; Enter again focuses the tab, and its workspace with it. `esc` unwinds a level before it closes the modal, so from the tab list it takes two presses to get out. `ctrl-n` creates whatever the level is listing and focuses it, matching what `prefix+shift+n` and `prefix+c` already do.

There is deliberately no worktree level between the two. herdr has one — `WorkspaceInfo.worktree` drives the indented sidebar grouping that `ui.sidebar.spaces.row_gap` describes — but it is null for every workspace `bin/herd` creates, because lines 132 and 207 use `workspace create --cwd` rather than `worktree create`. Registering the wtp pool after the fact is refused as well: `worktree open` returns `linked_worktree_source`, "new and open worktree actions start from the repo parent workspace", and `~/world/git` is bare, so every checkout under `~/world/trees` is a linked worktree with no parent workspace to start from.

The root picker offers the focused pane's cwd, every claimed `wtp` slot, and the worktrees of whatever repo the current root belongs to; it takes a typed path for anything else — an agent's output in `/tmp`, a file on the Desktop. Claimed means "on a branch", read from one `git worktree list --porcelain` against the pool's bare repo. `_wtp status` answers the same question but takes ten seconds, because it also computes dirty and unpushed per slot.

**Enter does one of three things.** herdr's socket API has no way to fire a built-in keybinding, so the Actions tab sorts every row into what this plugin can honestly do with it.

Most rows **run**: tabs, panes, splits, workspaces, worktrees, agent focus, resize steps, config reload, plugin actions, and this file's own commands. Three more were added by implementing the effect rather than the key — Settings opens `config.toml` in `$VISUAL` in a split, Edit scrollback dumps `pane.read --source recent_unwrapped` to a temp file and opens that, and Remove worktree picks a tree and asks twice before `worktree remove`. Last pane keeps its own trail from a `pane.focused` event hook, because herdr tracks that in client state no API can read.

Six rows **jump**: help, workspace picker, navigate mode, and the indexed `switch_tab` / `switch_workspace` / `focus_agent` are all herdr modals this launcher already replaces, so Enter moves to the tab that does the job. `switch_tab` lands on the current workspace's tab list, not the workspace list, because the row promised a tab.

Four rows **hand back the chord**: toggle sidebar, detach, open notification target, and resize mode. The first three are decoded in herdr's client and no API reaches them — `toggle_sidebar` is one bool in `AppState`, and detach is per-client by construction. Resize mode is a modal worth keeping for repeated resizing; the four discrete resize rows run. Enter raises the chord as a toast and closes. `ui.toast.delivery` is `off` here, so herdr answers `shown: false`, and the modal instead stays open with the chord in the header rather than eating the keypress.

Previews of a live pane are hard-truncated to the preview width rather than wrapped: a herdr pane is often 300 columns and wrapping that into 90 turns every line into three.

`prefix+?` stays bound. It is the fallback when the plugin is broken, and the launcher's Actions tab is built from `herdr --default-config` merged with this `config.toml`, so a herdr upgrade that adds a binding surfaces it automatically — ungrouped and display-only, but present.

A popup is a singleton, so a row that opens another popup (`tab-mover.pick`) is dispatched by a double-forked child that retries past `ui_busy` once this popup is gone. Rows that are themselves a command (`herd`, `lazygit`) `exec` in place instead, which is why they inherit the launcher's 90% geometry rather than the size set on their own binding.

Needs `fzf`; uses `fd` and `bat` when present and degrades to `find` and plain text without them.

### `tab-mover`

No longer local: authored here, then upstreamed as [shopify-playground/herdr-plugins#7](https://github.com/shopify-playground/herdr-plugins/pull/7) and now installed from that repo, pinned in `plugins.installs`. Its id lost the `sam.` prefix on the way, because the id is the first half of the keybinding string every consumer types into their own config.

Moves the active tab, panes and split layout intact, into another open workspace. `prefix+m` or `ctrl+alt+m` opens a modal picker listing the other open workspaces.

herdr has no cross-workspace tab move — `tab.move` only reorders tabs inside one workspace. The plugin rebuilds it from `pane.move`, the only call that relocates a live terminal, replaying the split tree from `layout.export` so directions and ratios survive. The source tab closes when its last pane leaves, and the source workspace closes with it if that was its only tab. Live agents keep running: a cross-workspace move reassigns the public pane id but the terminal and the agent name follow it.

Reordering a tab _within_ its workspace is not part of the plugin — herdr's built-in `keys.move_tab_previous` / `keys.move_tab_next` do it, bound in `config.toml` to `prefix+shift+comma` / `prefix+shift+period` and `ctrl+alt+shift+[` / `ctrl+alt+shift+]`.

No right-click entry: plugin v1 has no hook into herdr's native context menus, and `[[link_handlers]]` only fires on ctrl+click of a URL in terminal output. Asked for four times upstream and closed every time — herdrdev/herdr#1776 (closed `not_planned` by the author), #1671, #1830, #1511, and #3533. The feature as a _builtin_ is #3008 → discussion #3013. `osamahbeig/herdr-pane-mover` hit the same wall and ships the same action-opens-a-picker workaround.

**Known risk — herdrdev/herdr#3329 (open, reproduced on 0.8.2).** A cross-workspace `pane.move` resizes the terminal, and an alternate-screen app can end up with a permanently corrupt server-side grid: the process stays alive and accepts input, but the display never repaints and neither `ctrl+l` nor a forced SIGWINCH recovers it. #3686 is that report, closed as a duplicate of #3329, which is still open after 0.9.0. Moving a tab is N pane moves, so this applies here. A single-pane tab moving between same-width workspaces triggers no resize and is safe; a multi-pane tab resizes every pane during layout reconstruction even between identical workspaces. The `ui.pane_scrollbars = false` workaround in that thread targets a different trigger and does not help.

### `bin/herd` is the obvious next conversion

`bin/herd` is a herdr-only workflow already launched from three `type = "popup"` keybindings in `config.toml`. As a plugin it would get real `[[panes]]` entrypoints, `[[events]]` hooks, and a config dir, and drop out of `$PATH` where it does not belong.

## Layout templates

`layouts.toml` feeds the `worktree-layouts` plugin, which applies a tab/pane template on `worktree.created` and `worktree.opened`. **The file does not exist yet**, so both hooks currently no-op — the plugin is installed but inert. Create `personal/herdr/layouts.toml` and re-run `setup_herdr` (or symlink it by hand) to activate it. `layouts.example.toml` in the plugin checkout is the reference:

```bash
$(herdr plugin config-dir worktree-layouts)/../../github/worktree-layouts-*/worktree-layouts/layouts.example.toml
```

The plugin also reads a per-repo `<checkout>/.herdr/layouts.toml`, but only when `HERDR_LAYOUTS_TRUST_REPO=1` — it never auto-applies a repo-supplied template, since that would run commands from a checkout.

## Applying changes

`config.toml` edits reach a running server with `herdr server reload-config`. Plugin manifest changes need a server restart. `herdr --default-config` prints every option with its default.
